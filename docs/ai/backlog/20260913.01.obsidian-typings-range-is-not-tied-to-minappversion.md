# The `obsidian` typings range is not tied to `minAppVersion`, and now nothing moves it

## What happens

Three numbers describe the same thing and none of them agree. `package.json` declares `"obsidian": "^1.7.2"`, `manifest.json` declares `"minAppVersion": "1.11.4"`, and the caret range resolves to 1.13.1 in `pnpm-lock.yaml`. Nothing links them: `scripts/bump-plugin-version.mjs` reads `minAppVersion` only to write a `versions.json` row, and a caret range floats to the newest 1.x by construction.

The practical effect is that `tsc` sees every API up to 1.13.1 while the manifest promises the plugin runs on 1.11.4. The code already knows this — `src/main.ts` guards calls to APIs newer than the floor behind `requireApiVersion` — so the typings being ahead is deliberate in places. What is not deliberate is that no check states the relationship, so an ungated call to a 1.13 API typechecks and ships.

The 2026-09-13 Dependabot change added `ignore: dependency-name: obsidian` to `.github/dependabot.yml`, on the reasoning that the installed typings version is a decision to make beside `minAppVersion` rather than a weekly bump to take. That reasoning holds, but the entry froze the current misalignment rather than resolving it. On 2026-09-14 Dependabot version updates were removed from the repository altogether, `.github/dependabot.yml` with them, so there is now no recurring anything putting the drift in front of a human; `docs/releasing.md` says so and points here.

## How to observe

```bash
grep '"obsidian"' package.json          # ^1.7.2
grep minAppVersion manifest.json         # 1.11.4
node -p "require('obsidian/package.json').version"   # 1.13.1
```

## Why it matters

`minAppVersion` is a promise to users on older Obsidian builds: the directory sends them to the last plugin release that ran on their app. A typings floor that sits two minors above it means the compiler cannot enforce that promise, and the guard in `src/main.ts` is the only thing doing so, by hand, per call site.

## Likely directions

- Pin `obsidian` in `package.json` to the version that matches `minAppVersion`, so the compiler enforces the floor and a deliberate raise is one visible edit in two files. This is the shape that makes the `ignore` entry honest.
- Or keep the typings ahead on purpose and add a check asserting the relationship, plus a rule that any API above the floor is behind `requireApiVersion`.
- Either way, once the relationship is stated somewhere a check can read, a typings bump becomes a useful prompt rather than noise; whatever tool proposes bumps by then, do not exclude `obsidian` from it.
