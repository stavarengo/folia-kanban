# The detail panel suggests in two different ways, and one of them is Obsidian's

## What is asked

Noticed on 2026-08-29 while assignment (20260827.03) was being built, which added the fourth of the panel's suggesting inputs and made the split easy to walk into.

## Current behaviour

The card detail panel has four inputs that offer suggestions as you type, and they do not behave alike.

The **property name** box uses Obsidian's own type-ahead: `src/obsidian/propertySuggest.ts` extends `AbstractInputSuggest`, reached through the `suggestProperties` port on `CardRepository`. It is a real popup — arrow keys move through it, Enter picks, Escape dismisses it rather than closing the panel, and the rows carry a secondary note saying which list a name came from.

**Priority** (`src/ui/CardDetail.tsx:175`), **assignee** (`:239`) and the **relationship link** field (`:698`, one per relationship type the board declares) each use a plain `<datalist>`. That is the browser's control, not Obsidian's: it looks different, its keyboard behaviour is the browser's own, and it cannot say anything about a suggestion beyond the value itself.

Not a swap. `PropertySuggestion` in `src/model/properties.ts` is shaped around property names — `key`, a `group` of `"folia" | "board" | "vault"`, and `editedInPanel` for a name the panel edits through a control of its own. `propertySuggestions()` and the `PropertySuggestSource` port are typed against it. Suggesting a priority value, a person or a card through the same machinery means that type is no longer describing what it is named for.

The split predates assignment: priority and the relationship fields were already datalists. The entry exists because there are now four of them and the inconsistency reads as an oversight rather than a decision.

## How to observe

Open any card's detail panel and use the suggesting inputs in sequence: type into **Priority**, then **Assignee**, then a relationship field, then the empty **property** box at the end of the property list. The last one opens a styled popup you can walk with the arrow keys; the first three drop a browser list with different looks and different key handling.

## Why it matters

Four controls in one panel, doing the same job, answering the keyboard differently. A keyboard user learns the popup on one field and finds it absent on the next, and `Escape` in particular means two different things depending on which input has focus. It is also the kind of split that quietly sets a precedent: the fifth suggesting input will copy whichever neighbour it sits beside.

## Expected outcome

One suggestion behaviour across the panel's suggesting inputs — or a decision, written down in `docs/decisions.md`, that the split is right and what makes the property-name box the exception. Either answer settles what the next suggesting input should do.

## What the 2026-08-29 audit added

The audit that entry 20260829.07 commissioned (that entry is now done and deleted; the [report](../reports/20260829.what-obsidian-already-provides/README.md) is its result) counted this split and found it larger than described here.

Finding 01-06 counts **five** suggesting inputs, not four, answering the keyboard four different ways. The one this entry does not name is the board's search box, `src/ui/Toolbar.tsx:184-250`: roughly eighty lines of hand-built combobox, with `role="combobox"`, `aria-expanded`, `aria-controls`, `aria-activedescendant`, a `role="listbox"` of options and its own key handling. The finding reads that one as a **clear win** for `AbstractInputSuggest` — the plugin's most elaborate reimplementation of a control it already reaches natively elsewhere — while reading the three datalists as the cheaper, more arguable half.

Two smaller findings hang off the same controls, and belong to whatever decision this entry produces rather than to entries of their own:

- **01-12** — the search box's chrome (the wrapper, the magnifier, the clear button at `src/ui/Toolbar.tsx:186-221`) duplicates `SearchComponent`. Not worth doing on its own, worth doing if the box's suggester moves, because the input is being re-plumbed either way.
- **03-05** — `propertySuggestions` (`src/model/properties.ts:152`) matches by lowercase substring, where Obsidian's own suggesters use its fuzzy result model. Predictable and order-preserving as it stands; worth revisiting when a long vault's property vocabulary is hard to search.

The rest of the audit's related findings are in the report's own triage section.
