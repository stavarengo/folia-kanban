# A visual identity for Folia Kanban

## What is asked

Rafa asked on 2026-08-27 for the plugin to have a visual identity of its own: a logo and the elements around it (colours, type, the shapes a banner or an icon is built from), so that surfaces like the settings page, the README, and the community-plugin listing can carry something recognisable instead of a stock icon.

## Current state

There is no logo and no brand asset anywhere in the repository. The ribbon and the menus use Lucide's `layout-grid` icon (`src/main.ts`), `images/` holds a single screenshot (`card-detail.png`), and the README has no banner. What does exist is the design-token layer in `tokens/source/` (colour, typography, spacing, radius, shadow, motion, opacity, z-index, all mapped to live `--folia-*` CSS variables), which is the plugin's UI palette and rhythm; it is a natural anchor for a brand, but it is not one.

## Expected outcome

A small, documented identity: a logo (with a mark that works at ribbon-icon size and a wordmark for wider spaces), a colour choice that plays with the existing tokens and with both Obsidian themes, and guidance on how the pieces are used, delivered as source files kept in the repository so every later asset (the settings banner, a README header, the listing image) is derived from the same source. The name is "Folia Kanban"; the "folia" (leaves) reading is the obvious thread to pull, but that is a starting thought, not a decision.

## Why it matters

Two concrete consumers are already waiting: the settings-page banner (20260827.07) cannot be designed before the identity exists, and the community-portal listing is the first thing a prospective user sees. An identity decided once keeps those surfaces consistent instead of each inventing its own look.
