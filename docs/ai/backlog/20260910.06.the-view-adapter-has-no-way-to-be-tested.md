# The view adapter has no way to be tested

## What is asked

`src/view.tsx` holds the plugin's whole adapter between Obsidian's view lifecycle and the React board, and no test anywhere reaches it. Give it a test seam, then cover the behaviour that currently rests on reading the code.

## Current behaviour

Nothing under `test/` imports `src/view.tsx`, and `test/obsidianFake.ts` exports neither `FileView` nor `Scope` — its own header comment already anticipates the test that would need them. The fake is what lets the vault adapter be exercised, so the same route is open here; it just has not been built.

What that leaves unverified, as of 2026-09-10: the legacy `boardPath` migration in `setState`, the `rebindTo` path that drops the repository on a rename, the `onLoadFile` and `onRename` re-render, the keyboard scope built in the constructor, and the register/unregister lifecycle of the `/` shortcut, including the inversion that turns the board's "I took it" into the `false` Obsidian reads as "suppress this key".

The gap has a sharper edge than plain absence. The board's side of the shortcut is covered through a fake host in `test/ui.test.tsx`, and a fake can assert a contract the real adapter does not implement — during the fix of 2026-09-10 it briefly did, asserting that the board declines a `Ctrl+/` that the real view never offers it. A green suite around a fake host says nothing about the two halves agreeing.

## How to observe

Search `test/` for any import of `src/view.tsx`: there is none. Read `test/obsidianFake.ts` for `FileView` or `Scope`: neither is exported. Then change the sense of the return in the shortcut registration in `src/view.tsx` and run `pnpm verify`, which passes.

## Expected outcome

`KanbanView` can be constructed in a test against the Obsidian fake, and the behaviour above is asserted against the real adapter rather than a stand-in for it.
