# A nested subcard never surfaces under a search or filter

## What happens

A subcard with no `status` of its own is not a member of any column: `buildBoard` (`src/model/board.ts`) excludes every nested card from `board.columns` and puts it in `board.childrenOf[parent]` instead. `Column` filters only the paths it holds — `matchCard` runs over the column's own top-level bucket (`src/ui/Column.tsx`, the `globalFiltering` block) — and `SubcardGroup` renders `childrenOf` unfiltered, under whatever parent survived.

So a nested subcard is visible if and only if its parent matches the query, whatever the subcard itself says. It can carry a Blocked marker, an overdue date, unread comments or the very words you typed, and no filter will bring it up; conversely, a subcard that matches nothing still shows while its parent matches.

## How to reproduce

On the `feature-showcase` board, `Record the launch demo` is a subcard of `Plan the v1.0 launch` with no `status`, and it declares `blocked-by: ["[[Fix keyboard-drag focus bug]]"]`, so its tile shows *Blocked*.

- Click the **Blocked** chip (or type `is:blocked`): only `Draft the announcement post` is listed. `Record the launch demo` is gone, together with its parent, which does not match.
- Type `Record the launch demo` in the search box: nothing is found.
- Type `Plan the v1.0 launch`: the parent appears and the subcard comes back nested under it, still un-searched-for.

## Why it matters

The search box and the chips read as "show me everything on this board that is X". For nested work they silently mean "show me everything whose PARENT is X". A person who filters for what is blocked, overdue or unread gets an answer that quietly omits an entire class of cards, with nothing on screen saying a subtree was skipped — the failure mode that hides work rather than showing too much.

It also makes the sample vault's own tour slightly untrue: the relationships table in `examples/README.md` presents `Record the launch demo` as the "stated from the other end" blocked card, and the Blocked filter never shows it (that page now says so; the note goes away when this is fixed).

## Likely code areas

- `src/ui/Column.tsx` — `SubcardGroup` (renders `childrenOf` with no filter) and the `globalFiltering` block that filters top-level paths only
- `src/model/board.ts` — `childrenOf` / `columns` split, and `descendantsOf` (already walks the same tree)
- open question for whoever picks this up: should a matching subcard be lifted to the top level of some column while filtering, or should a non-matching parent be kept as a hollow container? Both change what "filtered board" means, so decide it before coding.
