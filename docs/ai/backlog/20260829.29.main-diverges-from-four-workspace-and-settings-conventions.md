# `src/main.ts` diverges from four Obsidian conventions, each cheap to change except for what changing it costs users

## What is asked

Findings 05-06, 05-08, 05-09 and 05-12 of the audit of 2026-08-29 ([section 05](../reports/20260829.what-obsidian-already-provides/05.workspace-views-commands-and-settings.md), with 07-08 in [section 07](../reports/20260829.what-obsidian-already-provides/07.guidelines-mcp-build-and-the-rest.md) pointing at the command ids). They live in one file and share one shape: the convention is written down, the code diverges, and the cost of converging is not the edit.

## Current behaviour

- The three command ids are `folia-open-kanban-board`, `folia-create-board` and `folia-convert-note-to-board` (`src/main.ts:140`, `:378`, `:387`), repeating a prefix Obsidian adds itself. The conventional ids are the unprefixed ones — but a command id is a stable identifier, so renaming silently drops any hotkey a user has bound, with no migration path (05-08). The scanner's rule for this tests for the full manifest id as a substring, which none of the three contains, so nothing flags it.
- `syncMarkdownActions` (`src/main.ts:241`) tracks the tab-header button on board notes with a marker class and a `querySelector` sweep over every markdown leaf, ignoring the payload the events it listens to already carry. The `addAction` bookkeeping has no better answer today (Obsidian offers no `removeAction` or id), but narrowing the event handling to its own payloads is small and self-contained (05-06).
- The two board-setup entries land in the file context menu's unsectioned tail, because `addBoardSetupMenuItems` (`src/main.ts:413`) assigns them no section. The typings say section ids are discovered by reading `data-section` off the rendered DOM, so adopting one means depending on an undocumented string (05-09).
- Three settings commit when the user leaves the field rather than as they type: `mcpPort` and `mcpBindAddress` are deliberately "held" (`src/settingsLayout.ts:201`, `src/main.ts:854`) because committing a half-typed port would bind the server to it, and `userName` is held for no such reason. Obsidian's settings style guide names commit-on-blur as the thing not to do, and names the alternative it prefers (05-12).

## How to observe

Bind a hotkey to a Folia command and read its id in `data.json`; right-click a note and see where "Create Folia board here" sits relative to the core groups; type into the MCP port field and watch when the value takes effect.

## Expected outcome

For each of the four, either the convention is adopted or the divergence is recorded as deliberate with its reason. The command ids in particular are a decision about a breaking change, not a rename: the finding suggests they are worth doing only alongside a release that already breaks something.
