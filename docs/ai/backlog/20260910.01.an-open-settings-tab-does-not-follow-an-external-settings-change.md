# An open settings tab does not follow an external settings change, and can write the old values back over it

## What happens

A running instance now reads `data.json` when Sync or a hand-edit changes it (`onExternalSettingsChange` in `src/main.ts`), and pushes what it read into every open board. The settings tab is not told: `refreshViews` only re-renders the Kanban views, so a `KanbanSettingTab` that happens to be open goes on showing the values from before the change.

Two of its fields make that worse than stale display. "Your name" and the two MCP server fields (port, bind address) are deliberately held and committed when the field is left rather than as the user types (`pendingUserName` and `pendingMcpFields` in `src/main.ts`, the held-field design in `src/settingsLayout.ts`). A field holding a value from before the external change commits that older value on blur, writing it straight back over what was just adopted.

Found by the review of the fix for `20260829.31`, which is where the callback came from.

## How to reproduce

Open Folia's settings tab, focus the "Your name" field, and while it is focused let another device's `data.json` arrive (or edit the file by hand). Click away: the name from before the sync is written back. Without touching a field, the same tab simply shows values the plugin is no longer running on.

## Expected outcome

A settings tab open while the file changes underneath shows what the plugin is actually running on, and a field the user did not edit never commits a value that predates the change.
