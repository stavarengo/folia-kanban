# Done subitems still render in their parent's column instead of a Done column

## What happens

A subitem — inline todo or subcard file — always renders wherever its parent card is placed, regardless of the subitem's own done/status state.

- Inline todos: `SubItem.done` is a plain boolean toggled from the checklist or the card's context menu. It has no column concept (see `src/model/types.ts`), so a checked-off inline todo just shows a checked box inside the parent card's "next todos" list (`CardItem.tsx`) — it cannot appear in a Done column because it was never a column-addressable thing.
- Subcard files: these do carry their own `status` frontmatter (`CardFrontmatter.status`), the same field an ordinary top-level card uses to pick its column. But `buildBoard` in `src/model/board.ts` marks every genuinely-nested child (`isGenuinelyNested`) as excluded from column placement ("real subcards are not on the board top level"), and builds `childrenOf` so `Column.tsx`'s `SubcardGroup` renders the child nested inside its parent's card, in the parent's column, no matter what the child's own `status` says. Setting a subcard's `status: done` does not move it into a Done column; it stays nested under the parent wherever the parent renders.

This matches the commit that introduced the nesting (`8eaba78`, "Jira-style subcard grouping"): "Child cards now render nested under their parent as a bordered, indented group inside the parent's column" — by design, at the time, independent of the child's status.

## Why it matters

Rafa: "Done items are still shown in the wrong column. I think they just show up wherever their parent ticket is shown (maybe this is related to the first item above)." Confirmed by the code: that is exactly the mechanism for subcards, and inline todos have the same symptom for a related reason (no column concept at all).

## Relation to the move-to-column request

See [20260825.01](./20260825.01.move-inline-subitems-to-other-columns.md). The code confirms a shared root cause for subcards specifically: `board.ts` excludes nested children from the columns model outright, which is both why a subcard's own status is never honoured for placement (this report) and why nothing lets a user drag/move it to a different column (the other report) — there is no column-assignment step for a subcard to hook into. Inline todos share the visible symptom (done work stuck under the parent) but for a narrower reason: they were never modeled with a column/status field to begin with, so there's nothing for a fix to "start honouring" — a column concept has to be added for them, not just consulted.

## Expected outcome

A subitem that is done — inline todo or subcard file — is not visually stuck in whatever column its parent occupies; it renders as done (e.g. in a Done column, or otherwise clearly separated from open work), with the same behaviour for both kinds of subitem.

## Likely code areas

- `src/model/board.ts` — `buildBoard`, `isGenuinelyNested`, `childrenOf`
- `src/ui/Column.tsx` — `SubcardGroup`
- `src/model/types.ts` — `SubItem`, `CardFrontmatter.status`
- `src/ui/CardItem.tsx` — inline "next todos" rendering
