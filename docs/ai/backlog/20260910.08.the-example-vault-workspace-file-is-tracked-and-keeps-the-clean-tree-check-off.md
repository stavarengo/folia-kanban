# The example vault's workspace file is tracked, and that keeps the release's clean-tree check off

## What happens

`examples/.obsidian/workspace.json` is tracked by git and Obsidian rewrites it every time the example vault is opened, resized or navigated. The working tree is therefore dirty almost whenever Obsidian is open, and every session that works in the vault has to remember to leave that file out of its commits.

`.release-it.json` sets `requireCleanWorkingDir: false` because of that churn. The cost of that setting is that release-it stages whatever is dirty into the release commit: any uncommitted change present when a release is cut ships inside `chore(release): x.y.z`.

## How to observe

Open the example vault in Obsidian, move a pane, and run `git status`. Then read `.release-it.json`.

## Expected outcome

Opening the example vault does not dirty the working tree, and a release refuses to run on a dirty tree, so nothing uncommitted can ride into a release commit.
