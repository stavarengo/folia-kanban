# The board measures the status bar itself, and does it in the wrong window

## What is asked

Finding 06-05 of the audit of 2026-08-29 ([section 06](../reports/20260829.what-obsidian-already-provides/06.interaction-and-input.md)). It was carved out of entry 20260829.36, which covered three findings; the other two (the `/` shortcut and the description preview's resize signal) were fixed on 2026-09-10 and that entry is gone.

## Current behaviour

`src/ui/App.tsx` queries `.status-bar`, measures its height once a board has loaded, and writes the result into a `--folia-statusbar-clearance` custom property. `src/styles.css` consumes it in two places (the column's bottom padding and the detail panel's), so the last card and the panel's last field clear the status bar Obsidian pins to the bottom of the window.

Two things are wrong with it. The query goes through `activeDocument`, which follows focus rather than naming the board's own document, so a board in a pop-out window measures whatever the focused window happens to have — the same class of bug entry 20260829.37 fixed for menus and portals, which deliberately left this one alone. And the measurement runs once per board load, so toggling the status bar afterwards leaves the clearance stale.

## What the audit recommended, and why it does not work as written

Finding 06-05 says to delete the measurement and the plugin variable and use Obsidian's documented `--status-bar-scroll-padding` instead. That was checked live against Obsidian 1.13.7 on 2026-09-10: the variable is not defined anywhere in the app's stylesheets and resolves to the empty string on `:root`, `body`, `.workspace`, `.workspace-leaf-content` and `.view-content`. Walking every accessible stylesheet for the name returns no rule at all. It is documented but not shipped, so swapping the measurement for it would silently drop the clearance to nothing. Whoever picks this up should re-check that on the Obsidian of the day and, if it is still absent, solve the two defects above on their own terms rather than by substitution.

## How to observe

Open a board in a pop-out window while the main window has focus, and compare the bottom padding the columns get with the pop-out's own status bar (a pop-out has no status bar at all). With a board already open, toggle Obsidian's status bar and watch the clearance stay where it was until the board reloads.

## Expected outcome

The clearance a board reserves matches the status bar of the window that board is actually in, and follows that bar when it changes.
