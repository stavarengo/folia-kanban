# Sending a todo to another column can do nothing at all, without saying so

## What happens

The column picker on a checklist line — in the card detail panel and in the right-click menu — goes through `moveTodo` (`src/ui/App.tsx`), which asks `moveSubtask` (`src/model/board.ts`) for the write to make. `moveSubtask` looks the line up in the board it was given, and returns `null` when that board has no such line. `moveTodo` then returns: no write, no message, and no reload either.

The board is a snapshot, and the panel can be reading a fresher note than the board behind it — a subtask added or removed a moment ago has not necessarily reached the board yet. In that window, choosing a column for a line does nothing whatsoever, and nothing on screen says so. The two neighbouring actions were made loud in the 2026-09-09 line-identity work: ticking a box and removing a todo both report when the board can no longer name the line, and both reload afterwards. This one was left as it was, which is why it now stands out.

Found by an unprimed review of that work, confirmed by running the model functions directly; not observed in a live Obsidian.

## How to reproduce

Open a card's detail panel on a note with two or more checklist lines. Remove one of them, and immediately — before the board's own reload lands — pick a column for a line below it. Nothing is written and no notice appears; the picker snaps back on the next reload.

## Expected outcome

An action that cannot be carried out says so, the way ticking and removing now do, and the board catches up afterwards. Whether the answer is a notice, a reload, or deciding the move from the reading the person is actually looking at (as the checkbox now does) is for the session that picks this up.
