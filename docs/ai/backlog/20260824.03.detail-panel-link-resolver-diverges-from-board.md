# The detail panel resolves subcard links differently from the board

## What happens

The board decides which card a `[[wikilink]]` in a `## Subtasks` list points to through `resolveLink` in `src/model/board.ts`: it accepts a folder-qualified target (`[[Tasks/Engineering/01-fix-export]]`), a `.md` suffix, a `#anchor`, a `|alias`, and it refuses to bind a bare basename that two cards share. The detail panel has its own tiny resolver, `resolveBasename` in `src/ui/CardDetail.tsx`, which only compares the raw link text against each card's basename and takes the first match.

So a subcard linked with any qualified form nests correctly under its parent on the board, while the parent's detail panel renders the same item as a missing link (`folia-link-missing`) with no navigation button. And where two cards share a basename, the board deliberately resolves to nothing while the panel silently picks whichever card came first.

## How to reproduce

In a board whose card folder has a subfolder, create `Cards/Engineering/Child.md` and make `Cards/Parent.md` link it as `- [ ] [[Cards/Engineering/Child]]`. On the board, Child nests under Parent. Open Parent's detail panel: the subtasks list shows the link as missing.

## Why it matters now

Since card titles can differ from file names (headings and the `title:` key), the panel's subcard rows are the one place where the raw link text and the card the board bound it to can visibly disagree. An unprimed review of that change surfaced the divergence; it predates it.

## Expected outcome

The detail panel and the board agree on which card a link refers to, including the refusal to bind an ambiguous basename. One resolver, used by both.
