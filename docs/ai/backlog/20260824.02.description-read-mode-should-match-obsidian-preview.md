# Description field's read mode doesn't match Obsidian's own rendering

## Problem

In the card detail panel, the DESCRIPTION field has its own custom "read mode" rendering (rendered markdown shown before switching to edit). See screenshot: the rendered markdown (numbered list with bold red "1 — PBS on the lab laptop", checkboxes, nested indentation) is styled by Folia's own renderer, not by Obsidian.

This custom renderer doesn't integrate well with the rest of the vault's look, especially when the vault has a custom theme installed — the styling (colors, list markers, spacing) can clash with or ignore the active Obsidian theme.

## Expected behavior

The description field's read mode should reuse Obsidian's own built-in "reading view" / preview rendering (the same one Obsidian uses to render a note's markdown normally), instead of a custom Folia-specific renderer. This avoids having to reimplement and keep in sync with every vault's theme peculiarities (custom CSS, snippets, community themes, callout styles, etc.) — Obsidian's own renderer already handles that correctly for whatever theme is active.
