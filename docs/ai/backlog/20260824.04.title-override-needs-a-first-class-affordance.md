# Setting a card's `title:` override has no first-class affordance in the app

## What happens

A card's frontmatter `title:` key overrides every other title source (see the README section "Where card titles come from"). Today the only in-app way to create that key is the custom-properties row in the detail panel: the person has to know the key exists and type `title` as a raw property name. Once the key exists, the row edits it coherently and the board tile follows, and inline rename on the board rewrites it; only creation is hidden.

Related gap: no example board demonstrates `card-title: heading` or `card-title: filename`. The feature showcase demonstrates only the default `auto` mode, through `04-tune-the-search-index.md` (heading) and `Ship the release notes.md` (`title:` key).

## Expected outcome

Someone who wants a card to display a title different from both its file name and its heading can discover and set that from the board or the detail panel without knowing the frontmatter key by heart. Whether that is a "Set display title" action in the card menu, a labelled field in the detail header, or something else is for the implementing session to decide.

If an example board for the explicit modes is added at the same time, it should keep `examples/README.md` in step, since `test/schema.test.ts` decodes every example note.
