# A card whose checklist uses any character other than x loses its subtask state

## What happens

Finding 04-15 of the audit of 2026-08-29 ([section 04](../reports/20260829.what-obsidian-already-provides/04.vault-files-and-metadata.md)).

`CHECKBOX_RE` (`src/model/card.ts:19`) accepts only `[ ]`, `[x]` and `[X]`. Obsidian's own rule is broader: a space means open and any other character means done, which is what the checkbox styling in themes and the metadata cache both work from, and it is what users get when they use any of the alternate checkbox characters Obsidian and its themes support (`[/]`, `[-]`, `[>]` and the rest). A card written or edited that way loses its subtask state in the board: the item is not counted, not shown as done, and the card's progress reads wrong.

The read path (`parseSubtasks` at `:345`, `parseSubItem` at `:330`, `cardStats` at `:402`) and the write path (`setSubtaskDone` and `tickLine` at `:476` and `:467`) share the same regex.

## How to reproduce

In the `examples/` vault, edit a card note by hand and mark one of its checklist items with a character other than `x` (for example `- [/] something`). Open the board and read that card's subtask count and the item's state in the detail panel.

## Expected outcome

The board reads a checklist the way Obsidian reads it. The finding is explicit that the wider question (reading subtasks from the metadata cache instead of from text) is not what this asks for — the write engine has to stay text-based, so the parser stays; it is the character class that is wrong.
