# The lint type program covers tests that no type-aware rule reads

## What happens

`eslint.config.mjs` enables `projectService` twice: once for `src/**` with the explicit type-aware rule list, and once at line 228 for a glob that includes `test/**`. `eslint --print-config test/ui.test.tsx` shows two active rules on a test file, neither of them type-aware, yet the type program is still built for the whole test folder on every run. The comment above line 228 justifies it through the obsidianmd preset, but that preset is re-globbed to `src/**` at line 203, so the justification no longer holds.

Measured on 2026-09-10: `pnpm lint` takes 7.3 seconds, of which about 4 is building and parsing the type program; narrowing the second `projectService` to `src/**` saves about 0.95 seconds with the same rules on the same files. The rest of lint's cost is type-aware rules over `src`, which is what they are for.

typescript-eslint's own guidance is to enable type information only for the files where type-aware rules run, and it ships a `disableTypeChecked` config for the others.

Decided on 2026-09-10: follow that guidance.

## How to observe

Run `pnpm exec eslint --print-config test/ui.test.tsx` and count the rules; then time `pnpm lint` with `TIMING=1`.

## Expected outcome

Type information is built only for files a type-aware rule reads. Lint reports exactly the same findings on exactly the same files as before, and `pnpm lint` is faster by the cost of the test-folder program.
