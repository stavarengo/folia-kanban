# Twelve of the board's components are drawn from scratch beside the variables Obsidian publishes for exactly those components

## What is asked

Twelve findings of the audit of 2026-08-29 ([section 02](../reports/20260829.what-obsidian-already-provides/02.styling-theme-and-design-language.md)) each name one control that Obsidian documents CSS variables for and that Folia styles without them: 02-17, 02-18, 02-19, 02-29, 02-32, 02-33, 02-34, 02-35, 02-37, 02-39, 02-40 and 02-41. They are one pass over one stylesheet, and several are a handful of declarations each.

## Current behaviour

- The detail panel's resize handle reinvents the app's divider (02-17), and the colour swatches reinvent the colour-input geometry (02-18).
- Dropdowns get no dropdown styling at all: `.folia-fields select` and `.folia-field select` are styled exactly like text inputs, using none of the six variables that exist for the control (02-19).
- Every input suppresses the focus outline and redraws its own ring, eight `outline: none` declarations, where the app publishes a focus border colour and a focus outline (02-29).
- Chips are a hand-built tag with none of the tag or pill variables (02-32); popovers are sized by hand where popover dimensions are published (02-33); both dialogs ignore the modal and dialog variables entirely (02-34).
- Checkboxes are drawn twice by hand, once as a 9px square marker with the file's only raw `border-radius` and once as a bare browser default (02-35); the subcard indentation guide (02-37), the comment blockquote (02-39) and the two "needs your attention" notice bars (02-40) each rebuild a shape the app already has variables for.
- The property rows reimplement Obsidian's own property editor (02-41), which is also the one place the finding warns against copying wholesale: `--metadata-label-width` is sized for an editor pane, and the detail panel is much narrower.

The findings split each of these into the free half and the judged half, and two of them depend on decisions held elsewhere: whether the dialogs become host dialogs at all, and whether the range input and the checkbox become `Setting` controls, both of which belong to the dialogs entry.

## How to observe

Open the detail panel and the edit-column dialog on a theme that restyles Obsidian's components, and compare each control against its equivalent in the app's own settings: the select, the focus ring, the checkbox and the dialog chrome are where the difference reads as a different program.

## Expected outcome

Each of the twelve controls either takes the app's variables for the parts that carry no design intent, or is recorded as deliberately Folia's. The finding texts already separate the two halves for each control, so the work is judgement rather than investigation.
