# The plugin claims mobile support it has never been built or tested for, and gates a Node import behind that claim

## What is asked

Two findings of the audit of 2026-08-29 meet at one line in `manifest.json`: 02-42 ([section 02](../reports/20260829.what-obsidian-already-provides/02.styling-theme-and-design-language.md)) and 07-01 ([section 07](../reports/20260829.what-obsidian-already-provides/07.guidelines-mcp-build-and-the-rest.md)). They ask for two different things and both are needed.

## Current behaviour

`manifest.json` declares `"isDesktopOnly": false`, which tells the community directory and every phone user that this plugin runs on mobile.

Nothing in the stylesheet supports that claim. `src/styles.css` contains exactly one media query, `@media (prefers-reduced-motion: reduce)`, and no `is-mobile`, `is-phone` or `is-tablet` selector at all, while Obsidian's own stylesheet carries 253 rules keyed on `.is-phone`, 156 on `.is-mobile` and 15 on `.is-tablet`. Hit targets are fixed at 24, 26 and 30 pixels, and several affordances are revealed on hover, which on a touch device is a usability problem rather than a styling preference. No script or test in the repository exercises a mobile viewport or platform class, and the report's live pass could not settle what Obsidian puts on `body` on a real device, because it had no device.

Separately, `src/obsidian/mcpHttpServer.ts:270` does `await import("http")` — a Node builtin — behind `if (!Platform.isDesktop) throw` at `:263`. The gating is correct, the lint rule that codifies the guideline accepts it, and the alternative (declaring the whole plugin desktop-only) is strictly worse for users. But the submission requirement's wording is unconditional, the reasoning exists only as a code comment, and `docs/decisions.md` has no entry for it, so a directory reviewer meets the manifest line with nothing to read.

## How to observe

Open a board in Obsidian on a phone and try to use it: read the hit target sizes, and try to reach anything that appears on hover. Then read `manifest.json` beside `src/styles.css` and `src/obsidian/mcpHttpServer.ts:263-270`.

## Expected outcome

Two deliverables. First, a decision on whether phones and tablets are supported, and the manifest and the stylesheet saying the same thing as each other whichever way it goes. Second, and independently of that answer, the position on the gated Node import written down where a reviewer can read it rather than living in a code comment.
