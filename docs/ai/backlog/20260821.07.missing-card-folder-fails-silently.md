# A card folder that does not exist looks exactly like a board with no cards

## What happens

Point a board's `card-folder` at a path that is not there — a typo, a folder that moved, a path copied from another vault — and the board opens perfectly. Columns render, the toolbar works, everything looks healthy, and there are simply no cards. Nothing anywhere says the folder was not found, so the only story available to the person looking at it is "this board is empty".

The same silence covers a second case. A board note with no `card-folder` property at all falls back to a hard-coded default of `Tasks`, so a board that never configured a card folder points at a folder most vaults do not have, and presents as empty for the same invisible reason.

There is a sharper consequence than confusion. Adding a card to that apparently-empty board calls `ensureFolder`, which creates the missing folder before writing the card. A typo in the property therefore turns into a real new folder in the vault, and the cards that were supposed to be on the board stay wherever they actually live.

## What already exists

Card selection is a plain string match: `loadBoard` takes every Markdown file in the vault and keeps the ones whose path starts with the card folder plus a slash. A folder that does not exist matches nothing, which is indistinguishable from a folder that exists and is empty. Nothing on that path ever asks the vault whether the folder is real.

The information is already in hand one function away. `loadContexts` looks the same path up with `getAbstractFileByPath` and returns early when the result is not a folder — so the plugin does learn that the folder is missing, on every single load, and throws that knowledge away.

Channels for saying so already exist and are used elsewhere. A failed load renders "Couldn't load the board: …" from `App`'s error state; action failures raise a toast; invalid frontmatter raises a `DataCorruptionError` that deliberately surfaces to the user rather than defaulting silently; and the plugin already shows a `Notice` when no board note can be found at all. A missing card folder is the odd one out.

## Expected outcome

Opening a board whose card folder cannot be found should say so, clearly enough that the person knows the board is misconfigured rather than empty, and specific enough to name the path that was looked for.

## Undecided

- Whether this reads as a hard load failure or as a message shown on an otherwise working board.
- What happens when a card is added to a board in that state, given that the folder is currently created on the spot.
- Whether the `Tasks` fallback for a board with no `card-folder` property should keep behaving as a silent default.
