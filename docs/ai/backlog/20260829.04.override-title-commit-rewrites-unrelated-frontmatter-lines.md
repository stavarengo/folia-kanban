# Committing an override title rewrites the note's whole frontmatter block, not just the title line

## What is asked

The card detail panel has an **Override card title** field. Committing a value there (Enter) writes `title:` into the card note's frontmatter. Observed on 2026-08-29 in a live verification run in Obsidian 1.13.7 on the `examples/` vault: that commit also rewrote the note's existing `tags` list into a different but equivalent YAML layout (for example flow style `[a, b]` turned into a block list, or the reverse), even though the user only touched the title.

## Current behaviour

The edit is semantically harmless — the `tags` value is unchanged, only its YAML shape is — and it was undone in that run. But the write touches lines the user never asked to change, which shows up as noise in diffs and in sync. The likely area, named here only as a location to check, not as a diagnosis: the frontmatter write path the panel uses, `processFrontMatter` usage in `src/obsidian/vaultRepo.ts` and the title-override commit in `src/ui/CardDetail.tsx`. Worth verifying as fact: Obsidian's `FileManager.processFrontMatter` re-serialises the entire frontmatter block on every call, not just the key being set, which would explain a change of this shape.

## How to reproduce

On the showcase board, open a card whose note has a multi-entry `tags` list written in flow style (`tags: [a, b]`). Set an override title in the detail panel and commit with Enter. Diff the note file.

## Expected outcome

Either an override-title edit changes only the `title:` line, or the project records a deliberate decision that whole-frontmatter-block re-serialisation on every override write is accepted, and why.
