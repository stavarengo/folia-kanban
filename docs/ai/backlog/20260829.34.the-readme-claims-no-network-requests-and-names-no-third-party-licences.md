# The README's privacy claim contradicts the MCP server, and three bundled dependencies ship no licence notice

## What is asked

Findings 07-18 and 07-19 of the audit of 2026-08-29 ([section 07](../reports/20260829.what-obsidian-already-provides/07.guidelines-mcp-build-and-the-rest.md)). Both are about what the repository's own documentation says, and both are small.

## Current behaviour

`README.md:345` opens a section headed "Your data stays yours", and its claim at `:347` reads: there is no database, no account, no sync service and no telemetry, and "the plugin makes no network requests at all". Thirty-two lines earlier, at `:315`, the README documents agent access over MCP at length, including the local HTTP server the plugin can be told to listen with. Both statements are defensible on their own terms and they sit in one file contradicting each other, in the section a privacy-minded reader trusts most.

Separately, `dist/main.js` bundles seven runtime dependencies (React, React DOM, the three dnd-kit packages, `yaml` and `zod`), all MIT or ISC, and three of them ship no licence comment that survives bundling. The repository supplies none either: the README's only licence content is its own badge and the project's AGPL line. Finding 07-19 is precise that the esbuild `legal-comments` setting is not the lever — it only moves comments that already exist — and that a third-party licences section in the README is what the policy actually asks for.

## How to observe

Read `README.md:315` and `README.md:345-347` together. Then grep `dist/main.js` for the licence notices of the seven bundled packages.

## Expected outcome

The privacy section stays true with the MCP server switched on, and the bundled dependencies' licences are named somewhere in the repository.
