# Option to expand/collapse a card's subitems within a column

## What is asked

Rafa: "Options to allow expand/collapse the subitems in the columns." He expects the same behaviour whether the subitems are inline todo items or full subcard files.

## Current behaviour

There is no collapse/expand affordance for a card's subitems today.

- Subcard files: `Column.tsx`'s `SubcardGroup` always renders the full nested subtree of a card's children ("Column renders each top-level card followed by a recursive subcard group walking the FULL subtree, so deeper descendants (grandchildren+) never vanish" — commit `8eaba78`). There is no state or toggle to hide that group; every descendant is always shown.
- Inline todos: `CardItem.tsx` always shows up to a fixed cap of undone todos (`stats.nextTodos.slice(0, cardNextTodos)`) directly under the card. There is no toggle to show/hide this list either — it's a fixed-count preview, not a collapsible section.

A repo-wide search for collapse/expand/fold UI in the board and card rendering code (`src/ui/*.tsx`, `src/model/*.ts`) finds no matches related to subitems — the only "expand"/"collapse" hits are an unrelated toolbar `aria-expanded` attribute, an unrelated column menu, and code comments about drag-and-drop visuals.

## Expected outcome

A per-card (or per-column) control that lets a user collapse a card's subitems out of view and expand them again, with identical behaviour for inline todos and subcard files.

## Likely code areas

- `src/ui/Column.tsx` — `SubcardGroup` (subcard rendering)
- `src/ui/CardItem.tsx` — inline "next todos" rendering (`cardNextTodos`, `stats.nextTodos`)
- `src/model/types.ts` — may need a `collapsed` flag surfaced somewhere (card-level UI state, not necessarily persisted to the note)
