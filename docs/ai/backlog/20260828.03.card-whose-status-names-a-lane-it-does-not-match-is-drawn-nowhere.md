# A card whose status names a lane it does not match is drawn nowhere

## What happens

A column can carry its own `filter:` rule, which turns it into an auto-populated lane: instead of showing the cards whose `status` names it, it pulls every TOP-LEVEL card on the board matching the rule, from wherever they live (`src/ui/Column.tsx`, `topLevelPaths`/`lanePaths`). Its own `board.columns` bucket is never read.

`buildBoard` still files cards into that bucket, because it files every card into the column its `status` names. So a card whose `status` says `research` while its properties fail `area:research` sits in a bucket nobody reads, in a column that pulls by a rule it does not pass — and no column draws it at all. It is not hidden by a filter the user typed; it is simply gone, with nothing on screen to say so, and the only way back is to edit the note's `status` by hand.

Dragging is how a user gets there without trying. Dropping a card into a lane sets its `status` to the lane's id like any other column (`#1.6`: the lane is a view, not an owner of membership, and a card may immediately fall out of it again) — and "falls out of the lane" turns out to mean "vanishes from the board".

Anything nested under such a card goes with it: a subcard renders under its parent, and its parent is nowhere.

## How to reproduce

1. Give a board a lane column, e.g. `{ id: "research", title: "Research", filter: "area:research" }`, alongside a plain `todo`.
2. Create a card with `status: research` and `area: home`.
3. It appears in no column. Drag any card into the Research lane for the same result without hand-editing a note.

## Why it matters

Losing a card is the worst outcome a board can produce, and this one is reachable by an ordinary drag. The search tally no longer compounds it — `filterVisiblePaths` (`src/model/board.ts`) asks whether a lane actually draws a card before counting it, so "N of M" tells the truth about the card being invisible — but telling the truth about a vanished card is not the same as not losing it.

## Likely code areas

- `src/model/board.ts` — `buildBoard`'s `effectiveColumnOf`/`place`: whether a lane id should be a valid `status` target at all, or fall back to the first column the way an unknown status already does.
- `src/ui/Column.tsx` — `topLevelPaths`/`lanePaths`: the alternative is for a lane to also draw its own bucket, which changes what a lane means.
- The move path (`moveCard` and `App`'s drop handling) decides what a drop into a lane writes, and is the third possible place to fix it.

All three change what a lane means, so this deserves a decision before code.
