# Obsidian's button styling out-specifies the plugin's text-buttons

## What happens

The plugin styles several buttons to read as plain text rather than as buttons — a link, a quiet label — by resetting `background`, `box-shadow`, `border` and `padding` on a single class. Obsidian's own stylesheet styles buttons through `button:not(.clickable-icon)`, which is a class plus an element and therefore out-specifies a lone class. The theme wins, and the button keeps a raised face and a drop shadow the plugin meant to remove.

Confirmed in the running app (Obsidian 1.13.7, default dark theme) by building an element in its real DOM context and reading its computed style: a `button.folia-link` inside `.folia-subtask` inside `.folia-detail` computes `background-color: rgb(51, 51, 51)` and an inset-plus-drop `box-shadow`, both supplied by `button:not(.clickable-icon)`. Enumerating the rules that match it and set a background returns exactly two, in this order: `button:not(.clickable-icon)`, then `.folia-link`.

`.folia-link` is the confirmed instance — it is the subcard row in the card detail panel's *Subtasks & subcards* list, so every subcard link there renders on a button face instead of as the text link it is written to be. The `.folia-card-parent-ref` rule hit the same trap and was fixed in `93524cb` by selecting through `.folia-card`, which is a second class and enough to win; that fix is the reason this was noticed at all.

## How to reproduce

Open a card with a `- [ ] [[Child]]` subtask in the detail panel and look at the child's row under *Subtasks & subcards*: the link sits on a slightly raised surface. It is subtle in a dark theme, where the button face is close to the panel background, and more visible in a light one.

## Why it matters

No test can see it. The suite renders in jsdom, which loads no Obsidian theme, so every one of these buttons computes exactly what the plugin's own rule says. The gap only exists in the running app, which is where the styling is judged.

It is also a class of bug rather than one bug: any future button styled to look unlike a button through a single class inherits it, and the failure is quiet — the control still works, it just looks wrong.

## Expected outcome

A button the plugin styles as text renders as text in the real app, and the way that is achieved does not depend on each author remembering this trap.

## Likely code areas

- `src/styles.css` — `.folia-link`, and the pattern shared by every text-styled button rule
- `src/ui/CardDetail.tsx` — where `.folia-link` is used
