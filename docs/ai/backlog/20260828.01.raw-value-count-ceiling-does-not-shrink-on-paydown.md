# The raw-value ratchet's count is a ceiling that never shrinks on its own

## What happens

`scripts/audit-raw-values.mjs` now allowlists each `(file, snippet)` pair with a `count` — how many times that exact value is tolerated in that file — and fails only when the observed count in the tree exceeds it (`docs/ai/backlog/20260826.11...` fixed the earlier bug where any count at all passed). But the check is one-directional: it never fails when the observed count is *below* the allowlisted ceiling.

So paying down debt (removing one occurrence of an allowlisted value, say going from two `320px` uses to one) leaves the allowlist still saying `count: 2`. Nothing shrinks it back down automatically, because the only thing that rewrites the allowlist is `--update`, and nobody is required to run it after a paydown. Until someone does, there is one unit of spare allowance sitting unused — and a later, unrelated change that reintroduces a second `320px` in that file will pass silently, exactly the kind of undetected drift the count was introduced to catch.

## How to reproduce

1. Take a file with an allowlisted entry of `count: 2` (e.g. `320px` if it ever gets a second use, or construct a fixture).
2. Remove one of the two occurrences. `pnpm audit:raw-values` still passes (observed 1 ≤ allowed 2) — correct, that's paying down debt.
3. Without running `--update`, add a *different* new occurrence of the same value back into the same file. `pnpm audit:raw-values` still passes (observed back to 2, still ≤ allowed 2) — this is the gap: this second occurrence was never reviewed or intentionally allowlisted, it just happened to fit inside the ceiling left over from the first one.

## Why it matters

The ratchet's stated job is that "new debt is blocked." A count that only ever grows what it tolerates (via `--update`, on purpose) but never shrinks on its own means paid-down debt quietly turns into spare capacity for different, unreviewed debt. This is a narrower, softer version of the original boolean-allowlist gap: instead of any duplicate passing forever, one unreviewed duplicate can pass per unit of debt someone previously paid down.

## Likely code areas

- `scripts/audit-raw-values.mjs` — `findNovel`'s comparison (`observed > allowed`) is where the ceiling is one-directional; that is also the only place that would need to change.
- Consider whether this is worth solving at all before working it: the current ceiling design was an explicit, scoped choice (see `tracking/waivers/0001-raw-value-debt.md`, "Fixed (2026-08-28)"), and tightening it further trades simplicity for a rarer failure mode.
