# The card parser is blind to code fences

## Problem

Nothing in `src/model/card.ts` tracks fenced code blocks. `headingIndex`, `sectionEnd` and the description boundary all match headings by line shape alone, so a note whose description contains a fenced snippet like

````markdown
```md
## Comments
- _2026-08-21 11:49:_ sample
```
````

is read as if that `## Comments` were a real section: the description stops at the fence's opening line and the sample text shows up in the comments list. Cards that quote Markdown — release notes, issue templates, plugin documentation, anything pasted from an agent — hit this.

`src/model/cardTitle.ts` already solves the same problem for its own scan (`FENCE_RE`, `fenceAfter`), so the shape of the answer exists in the repo.

The constraint worth carrying forward: the fix has to land on all of `headingIndex`, `sectionEnd` and the description boundary at once. Making only one of them fence-aware is worse than leaving them all blind, because the boundary and the section readers would then disagree about where a section starts, and the same text would show in two places while a save rewrites a section the user did not touch. `test/card.test.ts` pins the current blind behavior in a test explicitly marked as a known limitation; that test is the one to change.

## How to observe

Put the snippet above inside a card's description and open the card. The description is cut off at the opening fence and a stray comment appears.

## Expected outcome

Quoting the plugin's own section headings inside a card's body should be inert — the parser should see them as text, not structure.
