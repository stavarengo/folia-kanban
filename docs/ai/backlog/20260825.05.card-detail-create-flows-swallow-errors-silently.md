# The card-detail "create" and "add subcard" flows swallow errors silently

## What happens

Two of the three ways to create a card give no feedback at all when the create call fails.

In `CardDetail.tsx`'s `submitCreate` (the "Open details to create" add-card flow, `addCardFlow: 'detail'`), a failed `repo.createCard` is caught only to reset the in-flight guard: `catch { creatingRef.current = false; }`. Nothing is shown to the person — no toast, no inline message, no console-visible affordance in the UI. They typed a title, pressed Enter or clicked, and the panel just sits there having done nothing.

The "Add a subcard" input (also in `CardDetail.tsx`) goes through a local `mutate()` helper that has no error handling at all: `await fn(); await reload(); onChanged();`. A failing `repo.addSubcard` (which itself calls `createCard`) becomes an unhandled promise rejection with zero UI trace.

The third creation path — the inline add-card input in a column, `App.tsx`'s `onAddCard` — does report errors: it's wrapped in try/catch and routes to the existing toast mechanism (`reportError`). That fix landed as part of `docs/ai/backlog/20260821.07.missing-card-folder-fails-silently.md`, which is what surfaced this gap: a board can now show a friendly "the folder will be created when you add a card" notice, and then silently do nothing if the person's actual add-card interaction happens to be the "Open details to create" flow or "add a subcard," rather than the inline one.

## What already exists

`App.tsx` centralizes error reporting through `reportError`/`showToast`, and every mutation dispatched through the `BoardActions` object (`remove`, `setPriority`, `renameCard`, `moveWithinColumn`, `toggleTodo`, `removeTodo`, …) already follows a consistent `try { await repo.X() } catch (e) { reportError(e) } finally { await load() }` pattern. `CardDetail.tsx` has no equivalent — it isn't given a `reportError`-shaped callback, and its own `mutate()` helper and `submitCreate` don't use one.

This isn't specific to card-folder failures — any error from `createCard`, `addSubcard`, or anything else `mutate()` wraps (comments, subtasks, description edits) would be silently dropped the same way.

## Expected outcome

A failed create (or any `mutate()`-wrapped action) in the card detail panel should be visible to the person the same way every other mutation failure already is, instead of looking like nothing happened.

## Undecided

- Whether `CardDetail` gets its own access to the existing toast mechanism (threaded in as a prop/context) or whether `mutate()` grows a `catch` that surfaces some other way.
- Whether `submitCreate`'s guard-reset-only catch and `mutate()`'s missing catch should be fixed together (they're the same underlying gap) or as separate small changes.
