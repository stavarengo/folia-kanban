# The raw-value ratchet waves through a new copy of an already-allowed value

## What happens

`scripts/audit-raw-values.mjs` calls itself "a RATCHET: existing debt is tolerated, new debt is blocked". Its allowlist (`scripts/raw-value-allowlist.json`) stores each finding as `{file, snippet}` — no line number, no occurrence count — and the check passes a finding as soon as some entry with the same file and the same snippet exists.

So once `320px` is allowlisted anywhere in `src/styles.css`, a brand-new `320px` written anywhere else in that same file is accepted in silence. The ratchet only bites on a value that appears in a file for the very first time, which in a 2000-line stylesheet holding most of the repo's raw values is a small fraction of what it is meant to catch.

## How to reproduce

On `main`, `320px` occurs in `src/styles.css` once (`flex: 0 1 320px`) and is allowlisted. Add a second, unrelated `max-width: 320px` anywhere in that file and run `pnpm audit:raw-values`: it reports `OK (47 findings, all in allowlist)`. The same holds for every value already listed for that file.

Found while adding exactly such a declaration; that one has since been given a real token, so the tree is clean — the hole is not.

## Why it matters

The guard is one of the design system's load-bearing claims, quoted in `src/styles.css`'s header and in `tokens/source/README.md`: raw values live in the token block and nowhere else. A ratchet that silently accepts duplicates lets the stylesheet drift back to hard-coded values one copy at a time, and each copy looks approved by CI.

## Likely code areas

- `scripts/audit-raw-values.mjs` — the allowlist match (`{file, snippet}`), the `--update` re-baseline path, and its header comment
- `scripts/raw-value-allowlist.json` — the entry shape; a count or a line anchor per entry would make the ratchet real. Note that a line anchor churns on every edit above it, so a per-file-per-snippet count is probably the cheaper honest form.
