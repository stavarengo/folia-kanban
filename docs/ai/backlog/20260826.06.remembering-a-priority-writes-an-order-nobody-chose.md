# Remembering a priority writes a scale order nobody chose

## What happens

Setting a priority from the board makes the note learn *everything the board knows*, not just the value the user picked. `setPriorityAndReload` in `src/ui/App.tsx` builds its list from `boardPriorities(config.priorities, cards)`, which appends the values the cards happen to carry, sorted by severity tone and then alphabetically. `rememberPriorities` writes that list through verbatim.

For a board whose note has no `priorities` yet, every card value is an unknown word, so they all share one tone and the alphabetical tie-break decides the whole order. One priority edit turns that alphabetical accident into the board's written scale.

That order is now visible. A priority badge takes its colour from where the value sits in the note's list, so a board with cards carrying `later`, `now` and `soon` gets `priorities: [later, now, soon]` on the first edit, and `later` — the word alphabetically first, ranked by nothing — starts rendering as the strongest priority on the board. `sort: priority` follows the same order.

The colouring is deliberately conservative about this: a value that only lives on a card is left neutral precisely because its position in the derived vocabulary was not chosen by anyone (`priorityTone` in `src/ui/cardView.ts` says so). The learning step then writes that position into the note, and the caution stops applying.

## How to observe

Take a board note with no `priorities` property and three cards carrying `later`, `now` and `soon`. All three badges are grey. Right-click any card and set its priority to one of those words. Reopen the board note: it now holds `priorities: [later, now, soon]`, and back on the board `later` is red, `now` is orange-ish, `soon` is blue.

## Why it matters

The board tells the user, in colour and in sort order, that it knows how their words rank, when in fact it sorted them by spelling. It is also sticky: the note keeps the list, and nothing prompts the user to fix an order they never saw being written.

## Likely code areas

- `src/ui/App.tsx` — `setPriorityAndReload`, which decides what gets learned
- `src/ui/cardView.ts` — `boardPriorities`, which decides the order of what is learned
- `src/model/priorities.ts` — `mergePriorities`, which preserves that order on write
