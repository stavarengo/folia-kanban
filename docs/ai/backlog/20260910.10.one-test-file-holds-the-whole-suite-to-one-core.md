# One test file holds the whole suite to one core

## What happens

`pnpm test` takes about eighteen seconds on a many-core machine. `test/ui.test.tsx` alone takes 15.6 of them: it is one file of 6150 lines, 279 tests in 50 describe groups, and vitest schedules a file as one unit, so that file runs on one core while the other 28 files finish together in under five seconds and the remaining cores sit idle. Measured on 2026-09-10; pool and isolation settings (`forks`, `threads`, `--no-isolate`) change nothing, because they only affect per-file setup that is already hidden behind this one file.

The file grew across many fixes: every board-level behaviour added its describe group there. No group exceeds 1.8 seconds, so nothing in it is indivisible. A secondary cost inside the same file: 179 `userEvent.setup()` calls with default options, each yielding to a real timer between steps; removing that delay measured 3.5 seconds on its own, less once the file is split.

## How to observe

`pnpm exec vitest run --reporter=verbose` and compare the duration of `test/ui.test.tsx` with the sum of every other file.

## Expected outcome

The suite's wall time is bounded by the work, not by one file: `ui.test.tsx` is several files that vitest can spread across cores, the test count stays exactly what it was, and every test still renders what it rendered before.
