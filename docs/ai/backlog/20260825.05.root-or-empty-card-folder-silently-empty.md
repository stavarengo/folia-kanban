# A `card-folder` of `""` or `/` (the vault root) may still produce a silently-empty board

## What happens

`card-folder: ""` (explicitly quoted — an unquoted empty value becomes YAML `null` and falls back to the `Tasks` default correctly) and `card-folder: /` both normalize, through `cardFolderPath` + Obsidian's `normalizePath`, to a string identifying the vault root. What happens after that depends on behavior of `normalizePath` and `Vault.getAbstractFileByPath` that hasn't been confirmed against a live vault (the `obsidian` npm dependency ships only a `.d.ts`, no runtime, so this can't be checked from source alone):

- If `getAbstractFileByPath` resolves the root path to the vault's root `TFolder` (plausible, since the root always exists), the folder-exists check passes silently. But card selection then builds its prefix as `<root> + "/"`, and no real vault path starts with a doubled/root-anchored separator like that — so the board loads looking perfectly healthy with zero cards, which is the exact bug `docs/ai/backlog/20260821.07.missing-card-folder-fails-silently.md` was written to eliminate, just for this one input.
- Separately, `uniquePath` (used by `createCard`) also runs the target path through `normalizePath`, which could collapse a card path back down to the vault root — meaning a card "added" while in this state might get written to the root and then never match the (root-anchored) selection prefix, disappearing from the board it was just added to with no error shown anywhere.

## What already exists

This edge case predates `docs/ai/backlog/20260821.07.missing-card-folder-fails-silently.md` — before that item's fix, `card-folder: "/"` already produced a prefix that matched nothing, so the board was already silently empty for this input; the fix didn't make it worse, but it didn't close it either, and closing it needs the root-path plumbing (prefix construction, `uniquePath`) to treat "root" as a distinct, correctly-handled case rather than as a folder name.

A unit test in `test/board.test.ts` (`cardFolderPath("")` → `""`) documents the pure string-normalization step's behavior for this input, but nothing exercises what `VaultRepository` actually does with it against a real vault.

## Expected outcome

Someone should verify empirically (a live Obsidian vault, not the `.d.ts`) what `normalizePath("")` and `getAbstractFileByPath` return for the root, then either make root-anchored card selection actually work, or make the empty/root `card-folder` value surface the same "folder not found"-style notice this item's sibling entry (07) already added for a genuinely missing folder — rather than leaving it as a silent, empty-looking board.

## Undecided

- Whether `card-folder: "/"` (select every note in the vault as a card) is a mode worth supporting at all, or should be rejected/warned against outright.
