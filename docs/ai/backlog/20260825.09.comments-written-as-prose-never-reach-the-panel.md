# A `## Comments` section written as prose never reaches the panel

## Problem

The comments list only ever shows bullet lines. `parseTimestamped` in `src/model/card.ts` skips any line in `## Comments` (or `## History`) that does not start with `-` or `*`; a bullet without a recognizable timestamp is still shown, with an empty timestamp, so the gap is narrow: it is exactly non-bullet prose that vanishes.

That is the shape hand-written and agent-written notes actually produce. A section like

```markdown
## Comments

**2026-08-21** — Applied and checked against the test suite.
```

is invisible on the board while sitting untouched on disk.

The obvious fix is not safe as it stands. `updateTimestampedLine` and `removeTimestampedLine` walk the same section counting bullet lines only, and the panel addresses a comment by its index in the read order. Making the reader accept prose lines without changing the writers in the same step desynchronizes the two walks, so editing or deleting comment N rewrites a different line. Any change here has to move the reader and both writers together, and decide what editing a prose comment even means when there is no timestamp prefix to preserve.

## How to observe

Put the section above into any card of a board and open the card. The comments list is empty; the text is still in the file.

## Expected outcome

A person should be able to see what a note says under `## Comments` without having had to write it in the plugin's own bullet format, and editing from the panel must never rewrite the wrong line.

This was surfaced while fixing the description boundary (`## Question` / `## Answer` bodies showing empty) and deliberately deferred there: the description fix carried no such write-path hazard, this one does.
