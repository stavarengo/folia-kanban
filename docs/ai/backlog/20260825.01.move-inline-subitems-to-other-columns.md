# Allow moving a subitem to another column, whether it's an inline todo or a subcard file

## What happens

A card's `## Subtasks` checklist can hold two kinds of line, both modeled by the same `SubItem` type in `src/model/types.ts` (`kind: "todo" | "card"`, `done: boolean`): a plain inline todo, or a `[[wikilink]]` to a child card that is itself a full file (a subcard).

Neither kind can be moved to a column on its own.

- A plain inline todo has no column or status at all. `SubItem` carries only `text`, `done`, and a checklist `index`; there is nowhere in the data model to record which column it belongs to. `CardContextMenu.tsx` confirms the only actions available on a todo row are "toggle done" and "remove todo" (`a.toggleTodo`, `a.removeTodo`) — no move-to-column action exists.
- A subcard file does have its own `status` frontmatter (`CardFrontmatter.status` in `src/model/types.ts`), the same field that places an ordinary card in a column. But `buildBoard` in `src/model/board.ts` deliberately excludes every genuinely-nested child from column placement (`isGenuinelyNested` check, "real subcards are not on the board top level"), and `Column.tsx`'s `SubcardGroup` renders it with `useSortable` disabled — it's drag-clickable to open, but not drag-sortable across columns.

So today, changing which column a subitem's work shows up in is only possible by opening the child file (for a subcard) or the parent card (for either kind) and editing state by hand; there is no drag-and-drop or menu action that moves a subitem between columns.

## Why it matters

Rafa: "we need to allow moving subitems to other columns even when they are just inline todo items (not files themselves)." He expects the same behaviour whether the subitem is an inline todo or a full card file — one capability, not two.

## Relation to done-subitem placement

See [20260825.02](./20260825.02.done-subitems-render-in-parent-column.md): the reason a subcard's own status is ignored (it always renders nested in its parent's group, `board.ts` / `Column.tsx`'s `SubcardGroup`) is the same code path that blocks moving it — subcards are excluded from the columns model entirely, not routed to whatever column their status implies. Inline todos never had a column concept to begin with. The two reports may converge on one fix (giving subitems, of both kinds, an effective column derived from their own state) but the current code has two distinct gaps: inline todos lack a column concept altogether, while subcards have one (`status`) that the render layer never consults.

## Expected outcome

An inline todo and a subcard file both support being moved to a different column than their parent card's, and this shows up identically for both kinds of subitem.

## Likely code areas

- `src/model/types.ts` — `SubItem`, `CardFrontmatter`
- `src/model/board.ts` — `buildBoard`, `isGenuinelyNested`, `childrenOf`/`parentOf`
- `src/ui/Column.tsx` — `SubcardGroup`
- `src/ui/CardItem.tsx`, `src/ui/CardContextMenu.tsx` — todo rendering and its context menu (`toggleTodo`, `removeTodo`)
- `src/ui/Board.tsx` — drag-and-drop wiring for cross-column moves
