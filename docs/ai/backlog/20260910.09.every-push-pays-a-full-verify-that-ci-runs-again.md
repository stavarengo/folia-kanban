# Every push pays a full verify that CI runs again

## What happens

`lefthook.yml` runs `pnpm verify`, all nineteen checks over the whole repository, as a pre-push hook. Measured on 2026-09-10 on a many-core machine: about sixty seconds per push, serial. The `verify` job in `.github/workflows/pipeline.yml` runs the identical chain on every push to `main` and every pull request, so the hook buys the same result one minute earlier and nothing else. The hook file's own header says hooks are convenience and CI is authoritative.

Nothing depends on the hook any more: a release is cut on a runner, in the same pipeline run whose `verify` job passed on the commit the release is cut from, so removing the hook no longer removes the last verify before a tag.

The pre-commit hook is already scoped to staged files (eslint, prettier, markdownlint, in parallel) and is fast.

Of the nineteen checks, four accept a file list (eslint, prettier, markdownlint, ls-lint); tests can be narrowed to the files related to a change with `vitest related`; the other fourteen (typecheck, build, dependency-cruiser, knip, the token, raw-value, button, portal, waiver and a11y scripts, the community-scanner reproduction) scan fixed directories or need the whole project and cannot be scoped. A scoped pre-push would still take about forty-five seconds; a fully parallel one about twenty to thirty, bounded by the test suite.

Decided on 2026-09-10: follow the common practice for git hooks. Pre-commit runs only fast checks scoped to the staged files; pre-push runs nothing, or at most a fast subset such as typecheck and the tests related to the change; CI stays the authoritative gate. Whatever can be scoped to staged files and is not in pre-commit yet moves there.

## How to observe

`git push` any commit and time the `verify` line lefthook prints; compare with the CI run for the same commit.

## Expected outcome

A push is not slowed by checks CI repeats. Pre-commit runs every check that can be scoped to the staged files, and nothing else. `pnpm verify` remains the command to run on purpose before a release or a risky change, and CI remains the gate.
