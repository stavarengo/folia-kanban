# Give comments a visual "unread" state, and distinguish replies to mine

## What happens

Comments have no author and no read-state.

A comment is modeled by `Comment` in `src/model/types.ts` as just `{ timestamp: string; text: string }` — no author field exists anywhere in the type or in the on-disk format. `appendComment` in `src/model/card.ts` writes each one as a plain markdown bullet, `- _${timestamp}:_ ${comment}` (an italic timestamp prefix; older notes may still carry the legacy `- [${timestamp}] ${comment}` bracketed form, which the reader keeps supporting), under the card's `## Comments` heading; `updateTimestampedLine` edits it in place by index, again with no author. So today there is no way, from the stored data alone, to tell who wrote a given comment, let alone whether it was Rafa, another person, or an agent. Whatever authorship field this entry adds should extend that line grammar rather than replace it — it was deliberately kept extensible for this.

Rendering matches that: `CardDetail.tsx`'s `CommentItem` renders every comment identically (markdown text + its position/edit/delete controls), with no unread styling. `CardItem.tsx` shows a single aggregate badge on the card face in the column — `stats.comments` as an icon + count (line ~230) — which only ever grows; it doesn't flag that a comment is new or already seen.

## Why it matters

Rafa: "comments need to have this sense of not read yet... so I can have a visual clue on tickets that agents or other people have left comments and I have not read yet.... today, all comments look the same and I have no clue if any ticket has a comment that I should read, and I have no visual clue if any of my previous comments have been replied to."

He wants two distinct signals, not one:

1. A card has at least one comment he hasn't seen yet (in the column, and inside the card's detail panel).
2. One of his own earlier comments has since been replied to.

Signal 2 depends on knowing which comments are "his," which today's format cannot express at all — there is no author field to check against.

## Open design questions

- **Attribution**: nothing currently records who wrote a comment. Before "unread by Rafa" or "reply to mine" can mean anything, some form of authorship needs to exist — e.g. an author field in the comment line itself (a markdown-format, git-visible change) versus inferring "mine" from local read-state alone (no true authorship, just "I marked this one as mine/seen").
- **Where read-state lives**: the note file is the portable, git-tracked source of truth and is a poor fit for "has Rafa personally seen this" (it would mark a comment read for everyone with the file, including collaborators or synced devices). The plugin already has a small persistence mechanism outside the notes — `KanbanPlugin` in `src/main.ts` calls `loadData`/`saveData` for `KanbanSettings`, which is vault-local plugin data, not committed to the notes. A parallel per-vault (per-install) read-state store there is a candidate, but it wouldn't follow Rafa across machines/vaults the way the notes do, and it says nothing about multiple human collaborators reading the same vault.
- **"Reply to mine" detection**: with no threading model (comments are a flat, timestamp-ordered list under one heading), "replied to" can only be approximated — e.g. "any comment added after my last comment, on a card where I have a comment" — rather than a true reply relationship.

## Expected outcome

A card shows a visual cue, both in its column and in its detail panel, when it has a comment nobody (or not-Rafa specifically) has read yet, and a separate cue when one of Rafa's own comments has a newer comment after it. What generates or persists that state is left to whoever designs the fix.

## Likely code areas

- `src/model/types.ts` — `Comment` (would need an author field, if attribution is added)
- `src/model/card.ts` — `appendComment`, `parseTimestamped`, `updateTimestampedLine` (comment format/parsing)
- `src/ui/CardDetail.tsx` — `CommentItem`, the Comments panel
- `src/ui/CardItem.tsx` — the column-face comment badge (`stats.comments`)
- `src/main.ts` — `loadData`/`saveData` (existing vault-local persistence, a candidate home for read-state)
