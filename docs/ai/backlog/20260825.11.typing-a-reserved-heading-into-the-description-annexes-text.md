# Typing a section heading the plugin owns into the Description box quietly annexes the text

## Problem

`## Subtasks`, `## Comments` and `## History` are the plugin's own sections. Nothing on the write path says so. Type one of them into the Description box and save, and the text is written through verbatim; on the next read it is no longer description at all.

Concretely, saving this as a card's description:

```markdown
Intro

## History

of the project so far

- 2024: started
- 2025: shipped
```

leaves the Description box showing `Intro` alone. The line `of the project so far` is displayed nowhere, because the history reader skips non-bullet lines. The two bullets appear in the History list as entries with no timestamp, where the panel's delete button will remove them from the note, and the next card move appends its own `Moved from …` line into what the person wrote as prose. Description edits deliberately write no history entry, so there is no trail of any of it.

This behavior predates the description-boundary fix and is unchanged by it: the same input produces the same result against the parser as it was before that change. What the fix altered is how reachable it is. The Description box now holds everything up to the first owned section, headings included, and the README now tells people they may write their own headings there — so the chance of someone reaching for one of the three reserved names went up, while the consequence stayed silent.

## How to observe

Open any card, type the block above into the Description box, save, and reopen the card.

## Expected outcome

Writing one of the plugin's own section names in the description should not silently move a person's text into a structure they did not ask for, and certainly should not put prose where an automated writer will later append to it.

What "not silently" means is the decision to make: refusing the save with an explanation, escaping the heading so it stays description text, accepting it but saying what just happened, or treating it as legitimate and simply making the outcome visible. Each trades differently against the plugin's byte-stability rule, which is that a note is never reserialized beyond the region actually edited.
