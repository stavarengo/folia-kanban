# The MCP server only listens on loopback, so a client in a container cannot reach it

## What happens

`src/obsidian/mcpHttpServer.ts` binds the server to `MCP_HOST = "127.0.0.1"` and there is no setting to change that; the settings are `mcpEnabled`, `mcpPort` and `mcpToken` (`src/settings.ts`). Loopback is also leaned on as a security argument: `docs/mcp.md` says the token may live in `data.json` in the clear because "since the server is bound to loopback, anything that can read it already has your files".

A client that is not on the host cannot connect. The concrete case is this repository's own development flow: `AGENTS.md` describes driving Obsidian from a container through the Chrome DevTools bridge, and a Claude Code session in that container reaches the host only through the container's default gateway (`10.254.254.1` on the machine where this was found), which the host's loopback never sees. `curl http://10.254.254.1:27125/mcp` from the container is refused while the same request from the host answers. The same applies to any agent that runs in a VM, a devcontainer, or on another machine.

## How to observe

1. Enable agent access in the plugin on the host and confirm it answers on `127.0.0.1:<port>`.
2. From a container on the same machine, `curl -s -o /dev/null -w '%{http_code}' -X POST http://<gateway>:<port>/mcp` where `<gateway>` is `ip route | awk '/^default/{print $3; exit}'` run inside the container. Connection refused.

## Expected outcome

A user can choose where the server listens, with loopback staying the default and the choice made consciously: whatever the setting looks like, it must be plain that any address other than loopback lets other hosts on that network drive the vault with the token, and the reasoning in `docs/mcp.md` about the plain-text token has to be rewritten so it is still true when the bind is not loopback. The `Origin` check in `mcpHttpServer.ts` (which only accepts loopback origins today) needs the same treatment. The verification checklist in `20260821.04` should then work from a container without the relay its status note describes.
