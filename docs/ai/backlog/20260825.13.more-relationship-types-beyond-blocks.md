# Relationship types beyond "blocks", including ones the user defines

## What is asked

A card can now declare a typed relationship to another card, but exactly one type exists: `blocks`, stored as a list of wikilinks in the blocker's frontmatter and rendered in both directions (an editable **Blocks** field, a derived read-only **Blocked by** list, and a marker on each tile). Rafa named "a result of" as a second type he wants, and beyond that, types the user defines rather than ones the plugin ships.

Neither exists. A second built-in type has nowhere to be declared and nowhere to be shown; a user-defined one has no vocabulary to be declared in at all.

## How to observe it

Open any card's detail panel in the `examples/feature-showcase` vault. The only relationship control is **Blocks**. Adding `is-a-result-of: ["[[Some card]]"]` to a card's frontmatter by hand does nothing: the board preserves the key (frontmatter is free-form) and ignores it.

## Where the current version leaves the door

Relationships are addressed by type end to end: `RelationType` in `src/model/types.ts`, `RELATION_KEY` in `src/model/relationships.ts` mapping each type to its frontmatter key, `RelationLink` carrying `{ type, target, path, source }`, and repository methods taking a type (`addRelation` / `removeRelation`). Nothing in the stored format is specific to blocking beyond the key name and the label in `src/model/history.ts`. So this is an addition, not a migration of what people's notes already hold.

Two things the current version decided that a second type will have to face: `blocks` is written on ONE end only and the inverse is derived at load, and `blocked-by` is read as an explicit inverse but never written. A type whose two directions are not obviously "the same edge seen from two sides" may not fit that shape.

## Expected outcome

More than one relationship type is usable, and the notes written by the version that only had `blocks` keep working unchanged. What "user-defined" means concretely — where the vocabulary lives, what a type can carry, how it is displayed — is open and belongs to the session that takes this on.
