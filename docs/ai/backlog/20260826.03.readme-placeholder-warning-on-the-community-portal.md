# One warning is still open on the community portal's review

## Problem

The public listing at [community.obsidian.md/plugins/folia-kanban](https://community.obsidian.md/plugins/folia-kanban) carries a Review rating from Obsidian's automated scan of the latest release. Read on 2026-08-26 against release `0.0.19`, it said, verbatim:

- **Review: Satisfactory** (all four rating bars green), "2 issues found by automated scans of the latest release."
- **Warnings (1): "README contains unfilled placeholder text"** — detail: "All placeholder text (such as \"[description]\", \"TODO\", or template comments) must be replaced with real content describing the plugin." File listed: `README.md`.
- **Other (1)**: "Vault Enumeration: Enumerates all files in the vault (`vault.getFiles`, `getMarkdownFiles`, etc.)."
- Informational, not counted as issues: `AGPL-3.0` is a copyleft license; "Code uses runtime base64 encode or decode calls" (`atob`/`btoa`); "Malware scan not available"; "Obfuscation scan not available".
- Everything else passed, including build-verified-against-source and the artifact attestations on both release assets.

Only the README warning is actionable. The rest are structural — the licence is deliberate, a Kanban board over a vault necessarily enumerates it, and the two "not available" lines are the portal's own coverage, not ours. "Fully green" is not a state this plugin can reach, so that is no longer the goal.

The warning itself is not reproducible locally. `pnpm obsidian-scan:check` carries an *approximation* of this rule (its own comment says so — the real rule is published nowhere), and it reports nothing. The portal's itemised list is only visible on the maintainer's own account page, so the exact match is unknown.

The two suspects in `README.md`, in order:

1. The stale `> *Coming soon — Folia Kanban is awaiting review for the Obsidian community store.*` blockquote in the Install section. It was false — the plugin is in `community-plugins.json` — and it was removed on 2026-08-26, before this entry was rewritten. Whether it was *the* trigger is unproven.
2. The words `Todo`, `todo` and `WIP`, which appear about a dozen times as column names and product vocabulary. The local check is deliberately case-sensitive on `TODO` for exactly this reason. If the portal matches case-insensitively, these are the trigger — and they are not fixable without renaming concepts the product is built on.

## Expected outcome

Know which of the two it was, and either the warning is gone or it is recorded as a false positive we accept.

## How to verify

After the next release lands and the portal rescans (allow ~24h — see [docs/releasing.md](../../releasing.md) for why there is nothing to trigger), reload the public page:

- Warning gone → suspect 1 was it; nothing further to do.
- Warning still there → suspect 2, the product vocabulary. That is not a code change: it is a question for Obsidian staff about the rule's actual pattern, in the same escalation channels that doc describes.

## Status

Release `0.0.20` went out on 2026-08-27 at about 00:03 UTC, carrying the README without the stale blockquote. Reload the public page from 2026-08-28 onwards and apply the verification above.
