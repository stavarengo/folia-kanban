# Priority combobox forces predefined values instead of learning from the board

## Problem

The card detail panel's PRIORITY field is a combobox listing a fixed, predefined set of options (`urgent`, `high`, `medium`, `low`, plus a blank `—`). See screenshot: the board's cards already use a self-invented `a, b, c...` priority scheme (visible as badges on the cards: `a`, `b`, `c`), but the combobox for editing priority does not show `a`, `b`, or `c` as selectable options — only the predefined list, with the typed `a` value floating above it as free text.

This contradicts Folia Kanban's core principle of not enforcing any particular way of working. A user who has already established their own priority vocabulary shouldn't be nudged toward a different, predefined one every time they open the field.

## Expected behavior

- The priority field stays editable/freeform (typing a new value on the go must keep working, as it already does).
- The predefined suggestions (`urgent`, `high`, `medium`, `low`) should only appear as suggestions when the board has no priority values defined yet anywhere (i.e., no card in the board has ever set a custom priority).
- Once at least one custom priority value has been used on the board, stop showing the predefined suggestions. Instead, show the priority values that are currently in use or have been used before on that board (e.g. `a`, `b`, `c`).
- Every new/distinct priority value used should be persisted somewhere in the board's files (frontmatter) so it can be offered as a suggestion later, even after all cards using it are deleted or changed.
- If a board truly has no priority history yet, the initial suggestion set should follow the todo.txt spec convention: `A`, `B`, `C` (rather than the current `urgent/high/medium/low` word-based list).
