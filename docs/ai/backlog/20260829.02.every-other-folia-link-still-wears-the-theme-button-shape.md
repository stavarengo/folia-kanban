# Every other `.folia-link` still wears the theme's button shape, so a long one overflows its panel

## What is asked

Fixing 20260827.02 established that Obsidian's `app.css` gives every `button` two declarations that no wrapping text can survive: `white-space: nowrap`, so the text cannot break, and `height: var(--input-height)`, which pins the box to one text input's worth of height whatever it contains. That entry undid both, but only for the one row it was about. Every other `<button className="folia-link …">` in the plugin still carries them.

## Current behaviour

Measured in the running Obsidian on 2026-08-29, in the card detail panel: the "Why this title?" control and the inline subcard links inside a card's description all compute `white-space: nowrap` and a fixed height of one input, while sitting in a paragraph whose line height is about 17px.

The inline links are where it shows. Stretched to a realistic long card name, one rendered 599px wide inside a body 628px wide, overflowed that body by 15px and pushed its `scrollWidth` to 778. That is the same defect 20260827.02 was raised for, on the same class, in the same panel — a link whose text is longer than the space it has cannot wrap and pushes its container instead.

## How to reproduce

In the `examples/` vault, give a card a long name (a few hundred characters of ordinary words, and separately one unbroken token) and link it as a subcard of another card. Open the parent's detail panel and read the description section: check whether the link wraps, whether the body gains a horizontal scrollbar, and compare the element's `scrollWidth` against its container's `clientWidth`. The same reading on "Why this title?" shows the fixed height even where the text is short enough not to overflow.

## Expected outcome

A decision about where the undo belongs. Doing it once on `.folia-link.folia-link` in `src/styles.css` would cover every one of these, including the title row that already has its own copy, and would remove a per-element repair from the next person who hits this. Whether that is right depends on whether any `.folia-link` genuinely wants the theme's single-line button shape — the ones that sit in a row of controls may. Whatever is chosen needs coverage that survives jsdom, which cannot see any of this, and the answer should say what happens to the copy 20260827.02 left on `.folia-title-value`.
