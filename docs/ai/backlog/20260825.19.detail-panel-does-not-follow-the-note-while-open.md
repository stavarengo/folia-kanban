# An open detail panel does not follow its note, so the tile and the panel disagree

## What happens

`CardDetail` reads the card's body once, into local state: `reload()` runs from an effect keyed on `[path, isCreate]` and from `mutate()`, which wraps the panel's own writes. Nothing else refreshes it. The board around it does live-reload — `VaultRepository.onChange` schedules a reload on `vault.on("modify")`, and the tiles re-render from it.

So while a card's detail panel is open and an edit to that note arrives from anywhere else — another Obsidian pane, an agent writing straight into the file, Obsidian Sync, git — the board updates and the panel does not. The description, subtasks, comments and history shown in the panel are whatever the note said when it was opened.

This was always true, and it was mostly invisible: a stale description looks like a description. The unread-comments work made it visible, because the tile now carries a state the panel can contradict. An agent adding a comment to the card you are looking at turns the tile's comment badge blue (or purple, for a reply) *behind the panel*, while the panel itself shows no new comment, no `new` flag, and no `New` rule. The card is telling you two different things at once.

Reproduce: open a card's detail panel; in another editor, append a line under that note's `## Comments`; watch the tile light up while the panel stays as it was. Closing and reopening the panel resolves it.

## Why it matters

The panel is where the reading happens. A cue on the tile that the panel then fails to explain is worse than no cue: it sends you to a place that shows you nothing, and there is no visible reason why. It matters most in exactly the workflow the plugin is being built for — agents and other people writing into cards while Rafa has one open.

## Expected outcome

An open detail panel reflects the note it is showing, or says plainly that it is behind. Whatever shape that takes has to be careful about the panel's in-flight editing state: a description being typed, a comment half-written in the box, and a comment in inline-edit mode all hold text that a naive refresh would discard, which is presumably why the panel reads its body once in the first place.

## Likely code areas

- `src/ui/CardDetail.tsx` — `reload()`, the `[path, isCreate]` effect, `mutate()`, and the editing state (`descDraft`, `editingDesc`, `newComment`, `CommentItem`'s own draft)
- `src/obsidian/vaultRepo.ts` — `onChange` and the self-write echo guard (`recentWrites`), which is what tells an external edit apart from the panel's own
- `src/ui/App.tsx` — `load()`, the board-level reload the panel would hang off
